# Проверка: 3D по чертежу без фото + импорт с Циана (2026-10-13)

## Изменения

- `server/architectural-store.js` — очередь на генерацию больше не требует фотографий: достаточно плана этажа и габаритов (ширина/глубина/высота).
- `server/architectural-models.js` (`/analyze`) и `server/architectural-analysis.js` — разрешён пустой список фотографий при валидном плане.
- `worker/architectural_grounding.py` — **адаптивный порог растровой проверки** (Оцу по яркости, ограничен 80–210) вместо фиксированного `<100`: светло-серые маркетинговые планы (типичные для Циана) раньше гарантированно отклонялись. Для применения в боевом воркере нужен `docker compose build` образа.
- Тексты редактора и страницы объекта: фотографии отмечены как необязательные для 3D-планировки.
- `scripts/import-listing.js` — разовый импорт объявления (манифест + изображения) через публичный REST API; MIME определяется по сигнатуре байтов (CDN Циана отдаёт WebP под `.jpg`).
- Тесты: `tests/architectural-api.test.js` — кейс «план + размеры без фото → queued, analyze с пустым photos»; `tests/architectural_grounding_worker_test.py` — кейс со светло-серыми штрихами.

## Реальная генерация qwen3-vl: честный итог

Реальная генерация на этом плане **не прошла** — и защита сработала как задумано (некорректная геометрия не стала моделью):

- Поэтажный план девелопера светло-серый: штрихи стен 110–180 при пороге «тёмного» <100 → растровая проверка отклоняла даже верные стены. Исправлено адаптивным порогом (см. выше).
- Далее qwen3-vl:8b-instruct на этом плане неустойчив: часть запусков возвращает вырожденные наблюдения (стены = рамка изображения), часть — смещённую нижнюю стену (зацепка за дуги дверей/коридор под юнитом). Растровая проверка и проверка замкнутости корректно отклоняют такие ответы.
- Sanity-check на идеальном синтетическом плане: геометрию модель читает точно, но теряет флаги exterior и проёмы → `Missing exterior`. Т.е. конвейер работоспособен, ограничение — качество локальной 8B-модели на слабых входах.

Итоговое состояние объекта 55 — `failed`/`invalid_layout`, как после реальных неудачных попыток воркера; карточка остаётся опубликованной с фотографиями.

## Ограничения и заметки

- Вкладка десктопного браузера через browser-tools не запускала fetch к `/api/.../architecture` (секция не рендерилась); в Playwright/Chromium та же страница работает штатно — расхождение среды инструмента, не кода сайта.
- Генерация на RTX 3060 Ti идёт с частичной выгрузкой на CPU: 6–13 токенов/с, один заход анализа плана занимает 2–15 минут.
- `/tmp` в контейнере воркера ненадёжен для отладочных файлов — выводить артефакты в stdout.
