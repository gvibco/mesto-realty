Дата: 31.10.2026. Статус: утверждён пользователем.

Проект: «Место Бизнес» — B2B-площадка коммерческой недвижимости
(Node.js 22 + Express 5 + PostgreSQL, фронтенд на чистом JS без фреймворков,
SPA-роутинг в `public/js/app.js`, стили `public/styles.css`).

## 2. Админ-панель

**Кто админ:** пользователь, чей email (в нижнем регистре) совпадает с
`ADMIN_EMAIL` из окружения. Новая настройка `config.adminEmail`
(`server/config.js`), пример — в `.env.example`. Пустой `ADMIN_EMAIL` —
админов нет, все админ-маршруты отвечают 403.

**Сессия:** `GET /api/auth/session` дополнительно возвращает `isAdmin`
(сравнение email пользователя с `config.adminEmail`). Фронтенд при
`isAdmin === true` показывает в шапке ссылку «Админ-панель» (`/admin`).

**Middleware `requireAdmin`** (`server/security.js`): требует
`req.session.userId`, загружает email пользователя из БД и сверяет с
`config.adminEmail`; иначе 403 `{ error: "Недостаточно прав" }`.

**Права владельца расширяются до «владелец ИЛИ админ»** в существующих
эндпоинтах, чтобы админ мог работать с любым объявлением через уже готовый
редактор `/edit/:id`:

- `GET /api/properties/:id` — админ видит объекты любого статуса;
- `PATCH/DELETE /api/properties/:id` — функция `owned()` в
  `server/properties.js` принимает признак админа и снимает ограничение
  `owner_id`;
- загрузка/удаление фото (`server/uploads.js`) — тот же обход.

Признак админа вычисляется на сервере по сессии (запрос email при проверке),
не по данным клиента.

**Новый роутер `server/admin.js`**, подключается как
`app.use("/api/admin", adminRouter())`, все маршруты под `requireAdmin`:

| Метод | Маршрут | Назначение |
|---|---|---|
| GET | `/api/admin/stats` | Дашборд: всего пользователей, заблокировано; объявлений всего/опубликовано/черновиков/в архиве; по сделкам sale/rent |
| GET | `/api/admin/properties` | Все объявления всех владельцев (любой статус), владелец (имя, компания), фильтры `q`, `status`, `deal`, пагинация `page`, `limit` (1–48, по умолчанию 12) |
| GET | `/api/admin/users` | Список пользователей: id, имя, email, компания, роль, дата регистрации, число объявлений, `blocked`; пагинация |
| PATCH | `/api/admin/users/:id` | `{ "blocked": true|false }`; нельзя заблокировать себя (422); при блокировке удаляются сессии пользователя из таблицы `sessions` |
| GET | `/api/admin/content` | Текущие тексты главной из `site_settings` |
| PUT | `/api/admin/content` | Полная замена текстов: `heroTitle`, `heroText`, `commissionTitle`, `commissionText` (валидация zod, длина ≤ 300/1000) |

Публикация/архивирование/удаление объявлений из админки идут через
существующие `PATCH/DELETE /api/properties/:id` (с админ-обходом), а
редактирование — через штатный редактор `/edit/:id`. Отдельных
дублирующих эндпоинтов нет.

**Блокировка пользователей:**

- Миграция 006: `ALTER TABLE users ADD COLUMN is_blocked BOOLEAN NOT NULL DEFAULT false`.
- `POST /api/auth/login` отказывает заблокированному:
  403 `{ error: "Аккаунт заблокирован" }`.
- `GET /api/auth/session` для заблокированного уничтожает сессию и
  возвращает `user: null`.
- При `PATCH /api/admin/users/:id {blocked:true}` сервер удаляет строки
  пользователя из `sessions` (`DELETE FROM sessions WHERE (sess::jsonb->>'userId')::int = $1`).

**Тексты главной (site_settings):**

- Миграция 006: `CREATE TABLE site_settings (key TEXT PRIMARY KEY, value TEXT NOT NULL, updated_at TIMESTAMPTZ NOT NULL DEFAULT now())` + seed строк по умолчанию.
- Публичный `GET /api/content` (без авторизации; определён в `server/admin.js`,
  подключается в `app.js` до requireAdmin-роутов) возвращает тексты; при
  отсутствии записей — дефолты из кода.
- `home()` рисует дефолтные тексты сразу (нет скачков вёрстки), затем
  `GET /api/content` и при отличии заменяет `h1`, подзаголовок hero и тексты
  блока комиссии. Значения экранируются через `esc()`.

**Фронтенд `/admin`:**

- Новый модуль `public/js/admin.js`, лениво импортируется из роутера `app.js`
  при пути `/admin`; серверный regex отдачи `index.html` дополняется
  `admin`.
- Guard: `await sessionReady`; если `!state.user` → редирект `/login?next=/admin`;
  если `!isAdmin` → редирект `/` с тостом «Недостаточно прав».
- 4 вкладки по образцу кабинета (`forms.js`): **Дашборд** (карточки цифр из
  `/stats`), **Объявления** (таблица-список с фильтрами и действиями
  «Изменить» → `/edit/:id`, «Опубликовать/В архив», «Удалить» с
  подтверждением), **Пользователи** (список с кнопкой
  «Заблокировать/Разблокировать»), **Контент** (форма текстов главной,
  сохранение через `PUT /api/admin/content`).
- Стили — существующие классы кабинета/таблиц + минимум новых.

## 3. Тёмная тема

- **Cookie `theme`** со значениями `dark` | `light` | `auto` (по умолчанию
  `auto` = системная `prefers-color-scheme`), срок 1 год, `path=/`,
  не HttpOnly (ставится из JS), `SameSite=Lax`. LocalStorage не используется
  (соответствует правилам проекта).
- **`public/js/theme.js`** — маленький classic-скрипт, подключается в
  `<head>` `index.html` до `styles.css`-зависимой отрисовки: читает cookie,
  резолвит `auto` через `matchMedia("(prefers-color-scheme: dark)")`, ставит
  `data-theme="dark|light"` на `<html>` до первой отрисовки (без мигания).
  CSP не нарушается: внешний скрипт `'self'`.
- **Переключатель в шапке** (`index.html`, статичная разметка — без сдвига
  вёрстки): кнопка 🌙/☀️ с `aria-label`, между «Избранное» и «Войти». Клик:
  инвертирует текущую тему, обновляет `data-theme`, пишет cookie, обновляет
  `<meta name="theme-color">`.
- **Стили:** палитра `:root` расширяется до полного набора токенов
  (`--bg`, `--surface`, `--card`, `--text`, `--muted`, `--line`, `--blue`,
  `--blue-hover`, `--soft`, `--paper`, `--danger`, тени). Все ~78 жёстких
  литералов (`white`, hex) заменяются токенами или получают тёмные
  переопределения в блоке `html[data-theme="dark"] { … }` + точечных
  правилах для компонентов (карточки, hero, футер, модалки, тосты,
  ассистент, галерея, кабинет, фильтры). `color-scheme: light dark`.
- Тёмная тема покрывает все страницы, включая `/admin`.

## 4. Главная и заголовок по формуле 4U

Формула 4U: Useful (полезность), Urgent (срочность), Unique (уникальность),
Ultra-specific (ультраконкретность).

- `<title>` в `index.html`:
  «Место Бизнес — коммерческая недвижимость: 1% с продажи, аренда бесплатно».
- Hero (дефолты в коде, редактируются из админки):
  - eyebrow: «Коммерческая недвижимость для бизнеса»
  - **h1:** «Подберём помещение под ваш бизнес за 48 часов — платите только 1% при покупке»
    - Useful: подбор помещения под задачи бизнеса;
    - Urgent: за 48 часов;
    - Unique: плата только с покупки, аренда бесплатна;
    - Ultra-specific: «48 часов», «1%».
  - подзаголовок: «Офисы, склады и торговые площади напрямую от собственников. Размещение и аренда — бесплатно, комиссия 1% — только когда сделка продажи состоялась.»
  - кнопка: «Открыть каталог» (сохраняется).
- Заголовки секций главной слегка доводятся в духе 4U (конкретика и польза),
  структура секций (поиск, категории, новые объекты, города, комиссия) не
  меняется.
- Мета-теги `description` и `theme-color` обновляются соответственно.
- Название бренда «Место Бизнес» сохраняется (ребрендинг не запрашивался).
