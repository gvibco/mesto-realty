# Дизайн: 3D-планировка по чертежу без фотографий + тестовый импорт с Циана

Дата: 2026-10-13

## Цель

1. Архитектурная 3D-модель должна строиться по чертежу (плану этажа) и габаритам **без обязательных фотографий**. Фотографии, если есть, по-прежнему уточняют типы мебели. Режим «только фото» уже существует отдельно (Gaussian-splat по 20+ фото) и не меняется.
2. Проверить цепочку на реальном объявлении: найти случайное объявление о продаже помещения на Циане (с планировкой среди фото), импортировать все данные на сайт и получить 3D-модель.

## 1. Режим «чертёж без фото» (минимальные изменения)

Текущее состояние: очередь на генерацию требует план + ≥1 фото + габариты. Воркер (`worker/room_model_worker.py`) уже корректно работает без фото: `appearance()` возвращает пустой список мебели, цикл загрузки обрабатывает пустой `images`.

Изменения:

- `server/architectural-store.js` (`queueArchitecturalModel`): из условия `ready` убрать `images.length > 0`. Условие: категория ≠ `commercial_land`, есть `plan_filename`, заданы `width`/`depth`/`height`.
- `server/architectural-models.js` (роут `/analyze`): разрешить пустой список фото при валидном плане — убрать ветку `!images.length` из проверки исходных данных (план по-прежнему обязателен).
- Тексты UI:
  - `public/js/architectural-inputs.js`: help-текст — модель создаётся по плану и размерам; фотографии необязательны и лишь уточняют мебель.
  - `public/js/architectural-model.js`: сообщения состояний `needs_inputs`/«добавьте фотографию» — заменить на требование плана и размеров.
  - `public/js/forms.js` (строка подсказки в редакторе): аналогично.
- Тесты: обновить ожидания в `tests/architectural-api.test.js` (и смежных, если упадут): кейс «план + размеры без фото → `queued`»; существующие кейсы с фото сохраняются.
- Документация: `docs/architectural-models.md` — убрать утверждение «At least one photograph is needed», описать необязательность фото.

Вне области: миграции БД не нужны; Gaussian-splat конвейер не трогаем; требование ≥1 фото для **публикации объявления** сохраняется (это правило каталога, не 3D-конвейера).

## 2. Импорт объявления с Циана

- Новый скрипт `scripts/import-listing.js` (ESM, как остальной проект):
  - Вход: JSON-файл с данными объявления (title, deal, category, city, district, address, price, area, description, характеристики, габариты width/depth/height) + каталог со скачанными изображениями (фото и отдельно план).
  - Действия через REST API работающего сервера: регистрация/логин демо-аккаунта `import.demo@example.com` (пароль из переменной окружения `IMPORT_DEMO_PASSWORD` или аргумента), создание объявления, загрузка фото, загрузка плана, PUT габаритов, публикация. CSRF-токен берётся из `/api/auth/session`.
  - В конец описания добавляется строка: «Тестовый импорт с Циана, данные демонстрационные».
- Сбор данных: вручную-автоматизированно через браузерные инструменты (у Циана антибот-защита): поиск «продажа помещения», случайное объявление **с планировкой среди фотографий**, извлечение полей и скачивание изображений в `output/cian-import/` (не коммитится).
- Габариты width/depth для модели: выводятся из площади объявления и пропорций плана; высота — из поля «высота потолков» объявления (или разумное значение 3.0 м, если не указана — фиксируется в описании импорта).

## 3. Проверка на тестовом объявлении

1. `npm test` и `npm run test:api` — зелёные после изменений сервера.
2. Импорт реального объявления скриптом против локально запущенного сайта.
3. **Stub-прогон:** забрать задание через worker API (`POST /internal/architectural-models/claim` с `ROOM_MODEL_WORKER_TOKEN`), отправить валидную синтетическую сцену в `/complete`, открыть страницу объекта в браузере и убедиться, что 3D-планировка отображается.
4. **Реальная генерация:** если контейнеры `room-model-vision` и `room-model-worker` запущены — переинициировать задание (повторная загрузка плана), дождаться настоящей модели от qwen3-vl и проверить её в браузере. Если контейнеры недоступны — зафиксировать это в отчёте, stub-прогон остаётся доказательством цепочки.

## Критерии приёмки

- Объявление с Циана опубликовано на сайте со всеми полями, фотографиями и планом.
- При наличии плана и размеров без фотографий задание уходит в очередь (`queued`), модель генерируется.
- 3D-планировка отображается на странице импортированного объекта.
- `npm test` и `npm run test:api` зелёные.
