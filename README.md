# Место Бизнес — коммерческая недвижимость для B2B

## ИИ-помощник

Кнопка «Подобрать с ИИ» открывает чат для поиска опубликованных коммерческих объектов по требованиям посетителя. Ключ используется только сервером; диалог хранится в памяти вкладки. Помощник не изменяет объявления и не передаёт модели контакты, черновики или данные аккаунтов.

В переменных окружения сервера задайте `AI_API_KEY` и `AI_MODEL` (модель с поддержкой Chat Completions и function calling). По умолчанию используется OpenAI-совместимый endpoint `AI_BASE_URL=https://api.openai.com/v1`.

Для GigaChat задайте `AI_PROVIDER=gigachat`, `AI_BASE_URL=https://api.giga.chat/v1`, `AI_MODEL` (например, `GigaChat-2`), `AI_SCOPE` (`GIGACHAT_API_PERS` для физлиц, `GIGACHAT_API_B2B` или `GIGACHAT_API_CORP` для ИП и юрлиц) и ключ авторизации в `AI_API_KEY`. Сервер сам получает и кэширует access token на 30 минут. Корневые сертификаты Минцифры уже включены в образ (`certs/russian-trusted.pem`); для локального запуска задайте `NODE_EXTRA_CA_CERTS=./certs/russian-trusted.pem` в окружении перед запуском Node. После изменения настроек перезапустите контейнер. Если ключ или модель не заданы, чат работает в явно обозначенном режиме «Подбор по каталогу»: распознаёт город, назначение, аренду/покупку, бюджет с указанием рублей и площадь в м². Это поиск по правилам, а не ответы ИИ. После настройки модели сервер автоматически переключается на ИИ.

Интеграция использует протокол вызова функций OpenAI (Chat Completions) или GigaChat (`functions`/`function_call`). Поиск выполняется существующим SQL-сервисом с валидированными фильтрами: до 6 карточек за поиск, до 3 поисков за ответ, общий тайм-аут обращений к модели 25 секунд. Лимит — 10 сообщений в минуту на IP; сохраняются CSRF и ограничения общей API. GET `/api/assistant` возвращает `{enabled,mode:"ai"|"catalog"}`, POST принимает `{messages:[{role:"user"|"assistant",content:"..."}]}` и возвращает `{reply,properties}`. История — до 20 чередующихся сообщений, каждое до 2000 символов.

Русскоязычная площадка для арендаторов, собственников и брокеров коммерческой недвижимости на **HTML, CSS и JavaScript без фронтенд-фреймворков**, **Node.js + Express 5** и **PostgreSQL**. Все операции работают через REST API. Объявления, деловые профили, избранное и сессии сохраняются в PostgreSQL; фотографии — в постоянном каталоге `uploads/`. LocalStorage не используется.

## Быстрый запуск

Требуются Node.js 22+ и Docker Desktop / Docker Engine с Compose. Вместо Docker можно использовать собственный PostgreSQL 17+.

```bash
npm ci
npm run setup
docker compose up -d db
npm run db:migrate
npm run db:seed
npm start
```

Откройте **http://localhost:3000**. Для разработки: `npm run dev` (перезапуск Node при изменении серверного кода).

`npm run setup` создаёт локальный `.env` со случайными паролем БД и секретом сессий. Существующий `.env` никогда не перезаписывается. Для ручной настройки скопируйте `.env.example` в `.env`, заполните `POSTGRES_PASSWORD`, `DATABASE_URL`, `TEST_DATABASE_URL` и `SESSION_SECRET`. Сгенерировать секрет:

```bash
node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"
```

В PowerShell с запретом запуска `.ps1` используйте `npm.cmd` и `npx.cmd` вместо `npm` и `npx`.

PostgreSQL доступен только с локальной машины на порту **54329**. Если запускаете свою базу, создайте БД и укажите её URL, затем выполните миграции. Миграции версионируются в `schema_migrations`, выполняются транзакционно и защищены advisory lock от одновременного запуска.

### Демоданные

`npm run db:seed` создаёт **21 иллюстративное коммерческое объявление** (офисы, торговые помещения, склады, производство, свободное назначение и коммерческая земля) и 3 демонстрационных профиля компаний. Повторный запуск не создаёт дубликатов и не меняет существующие объявления. Фотографии и шрифты включены в репозиторий: для заполнения базы не нужны внешние сервисы.

Для проверки зарегистрируйте собственный аккаунт. Пароли демопрофилей по умолчанию случайные и не выводятся. Если нужны доступные демопрофили, задайте `DEMO_PASSWORD` **перед первым** заполнением базы; email: `anna.demo@example.com`, `mikhail.demo@example.com`, `elena.demo@example.com`. Повторный seed не сбрасывает пароли.

Адреса, цены и телефоны демонстрационные. Описание каждого демообъекта явно сообщает об этом. Источники фотографий и лицензия шрифта — в [public/assets/CREDITS.md](public/assets/CREDITS.md).

Docker-контейнер перед запуском приложения выполняет `npm run db:seed`: применяет миграции и добавляет недостающие демонстрационные объявления. Это позволяет загрузить примеры при развёртывании из Git на Dockhost. Существующие объявления не перезаписываются, дубликаты не создаются. Для запуска без демонстрационного наполнения переопределите команду контейнера на `npm start`.

При повторном запуске seed также восстанавливает отсутствующие первые фотографии известных демообъектов из включённых в проект иллюстраций, сохраняя их URL и существующие файлы. Для пользовательских загрузок на Dockhost подключите постоянный диск к `/app/uploads` (или своему `UPLOAD_DIR`): пересборка контейнера без диска теряет загруженные файлы, восстановить пользовательские оригиналы из базы невозможно.

## Возможности

- Главная: деловое оформление, поиск по городу/району, продажа/аренда, шесть коммерческих направлений, свежие предложения.
- Каталог: расположение, назначение, сделка, цена, площадь, класс здания, минимальная высота потолков и мощность, наличие парковки, сортировка и пагинация. Все параметры сохраняются в URL; фильтрация и пагинация выполняются SQL-запросами.
- Объект: галерея, описание, характеристики, контакты по кнопке, профиль автора, другие объявления автора.
- Комиссия сервиса: 1% от цены покупки и 40% месячной ставки при аренде, разово при сделке. В карточках отображается расчёт «Комиссия сервиса: … — X ₽». Размещение объявлений бесплатно.
- ИИ-помощник: кнопка «Подобрать с ИИ» в первом экране главной и подсказка под поиском; диалог подбирает объекты по каталогу.
- Тёмная тема: переключатель в шапке с иконками солнца/луны, выбор сохраняется в cookie `theme` (`dark|light|auto`, 1 год); `auto` повторяет системную тему. LocalStorage не используется.
- Админ-панель `/admin`: дашборд, управление любыми объявлениями, блокировка пользователей, назначение администраторов и редактирование маркетинговых текстов сайта.
- Регистрация, вход и выход; bcrypt с cost 12, серверные сессии в PostgreSQL.
- Кабинет компании: имя представителя, компания, роль (собственник / брокер / арендатор), телефон, описание и аватар; собственные объявления и избранное. Роль описывает участника, права на изменение определяются владельцем объекта.
- Создание, редактирование, удаление и снятие с публикации. Статусы: `draft`, `published`, `archived`.
- До 10 фотографий на объект, предпросмотр и удаление отдельных фото. Для публикации требуется минимум одна фотография.
- Характеристики: класс здания, этаж, потолки, электрическая мощность, парковка и условия НДС. Для коммерческой земли параметры здания не запрашиваются и очищаются сервером. Площадь всегда в м²; арендная цена — за весь объект в месяц, цена продажи — за весь объект.

Все основные текстовые поля обязательны и у черновика. Черновик позволяет сохранить заполненное объявление без фотографий. При сохранении опубликованного объявления редактор временно переводит его в черновик, загружает фотографии и публикует снова. При сбое черновик можно открыть из кабинета и завершить сохранение. Если потерян ответ самого первого создания, повторная отправка отключается до проверки кабинета, чтобы не создавать копии.

## Админ-панель

Администратор — аккаунт с флагом `users.is_admin` или email из переменной окружения `ADMIN_EMAIL` (регистр не важен; это бутстрап-админ, с него нельзя снять права). Других администраторов назначает действующий админ в разделе «Пользователи». После входа в шапке появляется ссылка «Админ-панель», а страница `/admin` открывает четыре раздела:

- **Дашборд** — счётчики пользователей, блокировок и объявлений по статусам и типу сделки.
- **Объявления** — поиск и фильтры по статусу и сделке; правка любого объекта через обычный редактор, публикация, перевод в архив и удаление.
- **Пользователи** — блокировка/разблокировка и назначение/снятие прав администратора. Заблокированный пользователь теряет активные сессии и не может войти («Аккаунт заблокирован», 403). Нельзя заблокировать себя, заблокировать `ADMIN_EMAIL`-аккаунт или снять права с себя и с `ADMIN_EMAIL`-аккаунта.
- **Контент** — маркетинговые тексты главной, каталога, карточки объекта, авторизации, подвала и SEO. Поля сгруппированы; значения хранятся в `site_settings`, публично читаются через `GET /api/content` и подменяют тексты по умолчанию сразу после сохранения. Подписи полей и сообщения об ошибках остаются в коде.

Админ-API защищено `requireAdmin`: 401 без сессии и 403 для остальных пользователей. Администратор проходит серверные проверки владельца там, где владелец изменяет свой объект; права определяются только на сервере.

## База данных

`users` (включая признаки блокировки `is_blocked` и администратора `is_admin`), `properties`, `property_images`, `favorites`, `sessions`, `site_settings` (маркетинговые тексты сайта), `schema_migrations`. Внешние ключи с каскадным удалением, уникальная пара `(user_id, property_id)` в избранном, уникальный email, проверки перечислений и числовых диапазонов. Цена — `NUMERIC(14,2)`, площадь — `NUMERIC(10,2)`.

Индексы покрывают владельца, опубликованные объекты по дате, сделку/категорию/цену, площадь, город/район, класс здания и технические параметры, фотографии, избранное и истечение сессий. Поиск по подстроке использует параметризованный `ILIKE`; для большого каталога можно добавить `pg_trgm` GIN-индексы по результатам профилирования.

### Обновление прежней версии

Миграция `002_commercial_b2b.sql` полностью убирает прежние жилые категории и старые демообъекты из базы, вместе с их связями фотографий и избранного. Пользователи и сессии сохраняются; прежние недемонстрационные объекты категории `commercial` становятся `free_purpose`. Поле `rooms` удаляется. Перед обновлением сохраните резервные копии БД и `uploads/`, затем выполните `npm run db:migrate` и `npm run db:seed`. Существующие деловые профили и пароли seed не перезаписывает. Невостребованные старые файлы в закрытом `uploads/` не раздаются без связанной записи объекта.

## REST API

Все ответы JSON, ошибка имеет вид `{ "error": "Понятное сообщение", "fields": { "поле": "причина" } }`. Изменяющие запросы требуют заголовок **`X-CSRF-Token`** и cookie сессии. Токен берётся из `GET /api/auth/session` и обновляется после регистрации/входа. Пустое избранное/каталог возвращают `items: []`; авторизация не подменяется клиентским состоянием.

| Метод          | Маршрут                               | Назначение                                                       |
| -------------- | ------------------------------------- | ---------------------------------------------------------------- |
| GET            | `/api/auth/session`                   | Пользователь и CSRF-токен                                        |
| POST           | `/api/auth/register`                  | `{name,email,password,company,businessRole}`                     |
| POST           | `/api/auth/login`                     | `{email,password}`                                               |
| POST           | `/api/auth/logout`                    | Уничтожить сессию                                                |
| GET / PATCH    | `/api/profile`                        | Приватный профиль / `{name,phone,bio,company,businessRole}`      |
| POST           | `/api/profile/avatar`                 | Multipart, поле `avatar`                                         |
| GET            | `/api/properties`                     | Поиск опубликованных объектов                                    |
| GET            | `/api/properties/:id`                 | Объект, автор, фото и другие объекты                             |
| GET            | `/api/properties/:id/contact`         | Контактное имя и телефон                                         |
| POST           | `/api/properties`                     | Создать черновик                                                 |
| PATCH / DELETE | `/api/properties/:id`                 | Изменить / удалить свой объект                                   |
| POST           | `/api/properties/:id/images`          | Multipart, повторяющееся поле `images`                           |
| DELETE         | `/api/properties/:id/images/:imageId` | Удалить своё фото                                                |
| GET            | `/api/me/properties`                  | Собственные объекты всех статусов                                |
| GET            | `/api/favorites`                      | Доступные опубликованные избранные объекты                       |
| POST / DELETE  | `/api/favorites/:id`                  | Добавить / убрать избранное                                      |
| GET            | `/api/health`                         | Проверить соединение с БД                                        |
| GET            | `/api/content`                        | Публичные маркетинговые тексты сайта                             |
| GET            | `/api/admin/stats`                    | Счётчики дашборда (админ)                                        |
| GET            | `/api/admin/properties`               | Все объявления с фильтрами `q`, `status`, `deal`, `page` (админ) |
| GET            | `/api/admin/users`                    | Пользователи с числом объявлений и флагом админа (админ)         |
| PATCH          | `/api/admin/users/:id`                | `{blocked?}` — блокировка, `{admin?}` — права админа (админ)     |
| GET            | `/api/admin/content-fields`           | Группы и подписи редактируемых текстов (админ)                   |
| GET / PUT      | `/api/admin/content`                  | Прочитать / сохранить маркетинговые тексты (админ)               |

Поиск принимает `q`, `deal=sale|rent`, `category=office|retail|warehouse|industrial|free_purpose|commercial_land`, `minPrice`, `maxPrice`, `minArea`, `maxArea`, `buildingClass=A|B|C`, `minCeilingHeight`, `minPowerKw`, `parking=true|false`, `owner`, `sort=newest|price_asc|price_desc`, `page`, `limit` (1–48; по умолчанию 12). Ответ: `{items,total,page,pages}`. Неподдерживаемые категории и поле `rooms` API отвергает с кодом 422; интерфейс очищает устаревшие параметры старых ссылок.

Поля объявления: `title`, `deal`, `category`, `city`, `district`, `address`, `price`, `area`, `description`, `contactName`, `contactPhone`, `status`, `buildingClass`, `floor`, `ceilingHeight`, `powerKw`, `parking`, `tax`. Дополнительные характеристики необязательны. `tax`: `included` (НДС включён), `excluded` (без учёта НДС), `no_vat` (НДС не облагается), `unspecified` (не указан). `parking` — boolean, пустые числовые параметры — `null`.

PATCH также поддерживает изменение одного поля, например `{ "status": "archived" }`. Сервер проверяет полную результирующую запись. Чужие и недоступные объекты возвращают 404. Публичный автор содержит `company` и `businessRole`, но публичные DTO не содержат email, хеша пароля, ключей демоданных или содержимого сессий; собственный профиль включает email только для авторизованного владельца. `company` необязателен (до 120 символов), `businessRole`: `owner`, `broker`, `tenant`.

## Безопасность и production

- Пароль 10+ символов, не более 72 UTF-8 байт; bcrypt cost 12.
- Cookie `mesto.sid`: `HttpOnly`, `SameSite=Lax`, срок 7 дней, `Secure` в production. Идентификатор сессии и CSRF-токен заменяются при входе.
- Synchronizer CSRF token, проверка `Origin`, параметризованный SQL, разрешённые значения сортировки, серверная проверка владения.
- Ограничения: 20 запросов авторизации за 15 минут на IP, 20 загрузок/мин, 30 запросов контактов/мин, общий лимит 300 API-запросов/мин. Счётчики ограничений находятся в памяти одного процесса; для нескольких экземпляров используйте общий store и лимиты reverse proxy.
- Helmet/CSP, `no-store` для API и media, экранирование пользовательского текста, отсутствие inline-скриптов.
- Принимаются только JPEG/PNG/WebP, до 8 МБ каждый, максимум 40 млн пикселей. Sharp декодирует содержимое, сверяет формат с MIME, удаляет метаданные и перекодирует в WebP; анимации отвергаются. Файлам назначаются случайные UUID. Каталог `uploads/` не раздаётся статически.
- Изображения черновиков и снятых объектов доступны только владельцу; публичный доступ прекращается сразу после смены статуса. Последнюю фотографию опубликованного объекта удалить нельзя.

Для production задайте `NODE_ENV=production`, `APP_ORIGIN=https://ваш-домен`, постоянный `SESSION_SECRET`, URL PostgreSQL с подходящими настройками TLS и `ADMIN_EMAIL` (email бутстрап-администратора; дальнейших администраторов можно назначить в админ-панели). Запускайте Node за HTTPS reverse proxy, например Nginx или Caddy. Если между браузером и Node ровно один доверенный proxy, задайте `TRUST_PROXY=1`; порт Node должен быть доступен только этому proxy. Без HTTPS production-запросы отклоняются. Настройка сессий следует [официальной документации express-session](https://github.com/expressjs/session#cookiesecure).

Сохраняйте резервные копии **и PostgreSQL, и `UPLOAD_DIR`**. Перезапуск `npm start` и `docker compose restart db` сохраняет данные. Команда `docker compose down -v` удаляет том базы — не используйте её для обычной остановки. Перед сетевым запуском замените демонстрационное содержимое своими объявлениями.

## Проверки

```bash
# Быстрые проверки схем данных
npm test

# Создать отдельную тестовую БД один раз
docker compose exec db createdb -U mesto mesto_test

# API + миграция старой БД + HTTPS/Secure-cookie + ограничения запросов
npm run test:api

# Полный браузерный сценарий в Chromium
npx playwright install chromium
npm run test:browser

# Форматирование и аудит производственных зависимостей
npm run format:check
npm audit --omit=dev

# Проверки перед пушем: тесты, формат, аудит зависимостей и мусор в git
npm run preflight

# Контроль живого сайта после деплоя, включая правдоподобность ответов ассистента
npm run verify:live
```

Тесты API и браузера требуют `TEST_DATABASE_URL` на отдельную базу с именем, заканчивающимся на `_test`. Они не используют основную БД. Браузерный тест сам запускает сервер на **3101**, создаёт временные фотографии, выполняет сценарий и удаляет тестового пользователя; сохранённые скриншоты — `output/playwright/` (не включаются в Git).

Проверяются регистрация → выход → вход → создание с двумя фото → публикация → поиск → избранное → редактирование → снятие и повторная публикация → удаление. Дополнительно: коммерческие категории и фильтры, поля компании, миграция старой базы, профиль/аватар, экранирование HTML, права другого пользователя, фальшивые/слишком большие изображения, CSRF, уникальность избранного, сохранение сессий при пересоздании сервера, адаптивность и восстановление после сетевых ошибок. Итоги B2B-проверок: [docs/b2b-verification.md](docs/b2b-verification.md).
